# অফিস জেনারেল স্টোর ব্যবস্থাপনা (Office General Store & Inventory Management)

একটি সম্পূর্ণ ফ্রন্টএন্ড (HTML/CSS/JavaScript) ওয়েব অ্যাপ্লিকেশন, যা অফিসের **General Store / Central Store** পরিচালনার জন্য তৈরি। কোনো ব্যাকএন্ড ছাড়াই এটি সম্পূর্ণভাবে **GitHub Pages**-এ ফ্রি হোস্ট করা যায়। এটি বিক্রয়/ই-কমার্স সফটওয়্যার নয় — এর মূল কাজ হলো মালামাল ক্রয় (Stock In) ও বিভিন্ন দপ্তরে মালামাল বিতরণ (Stock Out)-এর হিসাব রাখা।

## Features

- ড্যাশবোর্ড: মোট মালামাল, মোট স্টক, মাসিক ক্রয়/বিতরণ, লো স্টক ও আউট অফ স্টক অ্যালার্ট, সাম্প্রতিক কার্যক্রম
- মালামাল ব্যবস্থাপনা: Add/Edit/Archive, ক্যাটাগরি ব্যবস্থাপনা
- Stock In (মালামাল ক্রয়) এন্ট্রি ও হিস্ট্রি, ফিল্টারসহ
- Stock Out (দপ্তরে মালামাল প্রদান) এন্ট্রি — অপর্যাপ্ত স্টক থাকলে বাধা দেয়, নিশ্চিতকরণ ডায়ালগসহ
- দপ্তর ব্যবস্থাপনা (Add/Edit/Archive)
- সম্পূর্ণ লেনদেনের ইতিহাস (Opening/In/Out), ফিল্টার ও CSV এক্সপোর্ট
- রিপোর্ট: দপ্তর-ভিত্তিক রিপোর্ট, মালামাল-ভিত্তিক লেজার (Stock Ledger), বর্তমান স্টক রিপোর্ট
- মাসিক হিসাব (Opening/In/Out/Closing, দপ্তর-ভিত্তিক সারসংক্ষেপ)
- প্রিন্ট-উপযোগী রিপোর্ট লেআউট (Prepared/Checked/Authorized By সহ)
- আর্কাইভ (Delete-এর পরিবর্তে Archive, পরে Restore বা স্থায়ী মুছে ফেলা যায়)
- JSON ব্যাকআপ ডাউনলোড ও রিস্টোর
- CSV এক্সপোর্ট (Transaction History, Current Stock)
- localStorage-এ ডেটা সংরক্ষণ — Refresh বা Browser বন্ধ করলেও ডেটা থাকে
- সম্পূর্ণ বাংলা ইন্টারফেস, Desktop-first ও Mobile Responsive ডিজাইন

## Local Computer-এ Run করার নিয়ম

কোনো সার্ভার প্রয়োজন নেই। শুধু `index.html` ফাইলটি ব্রাউজারে (Chrome/Edge/Firefox) সরাসরি ডাবল-ক্লিক করে খুলুন। সব ফিচার তৎক্ষণাৎ কাজ করবে।

চাইলে VS Code-এ **Live Server** এক্সটেনশন দিয়েও চালাতে পারেন — এটি ঐচ্ছিক, বাধ্যতামূলক নয়।

## GitHub-এ Upload করার নিয়ম

1. [github.com](https://github.com)-এ আপনার অ্যাকাউন্টে Login করুন।
2. উপরে ডানদিকে **+** আইকনে ক্লিক করে **New repository** নির্বাচন করুন।
3. Repository Name দিন: `office-store-management`
4. **Public** নির্বাচন করে **Create repository** বাটনে ক্লিক করুন।
5. তৈরি হওয়া রিপোজিটরি পেজে **uploading an existing file** লিংকে ক্লিক করুন।
6. নিচের ফাইল/ফোল্ডারগুলো টেনে এনে (drag & drop) আপলোড করুন:
   - `index.html`
   - `style.css`
   - `script.js`
   - `README.md`
   - `assets` ফোল্ডার (ভিতরে `logo.png` সহ)
7. নিচে **Commit changes** বাটনে ক্লিক করে আপলোড সম্পন্ন করুন।

## GitHub Pages Enable করার নিয়ম

1. আপনার রিপোজিটরির উপরের মেনু থেকে **Settings**-এ যান।
2. বাম পাশের মেনু থেকে **Pages** নির্বাচন করুন।
3. **Build and deployment** সেকশনে **Source** থেকে **Deploy from a branch** নির্বাচন করুন।
4. **Branch** থেকে `main` নির্বাচন করুন এবং ফোল্ডার হিসেবে `/ (root)` নির্বাচন করুন।
5. **Save** বাটনে ক্লিক করুন।
6. কিছুক্ষণ পর (সাধারণত ১-২ মিনিট) পেজের উপরে একটি সবুজ বক্সে আপনার ওয়েবসাইটের URL দেখাবে, যা এমন হবে:
   ```text
   https://<your-username>.github.io/office-store-management/
   ```
7. এই লিংকে গিয়ে সফটওয়্যারটি ব্যবহার শুরু করতে পারবেন।

## Data কীভাবে সংরক্ষণ হয়

সব তথ্য (মালামাল, ক্যাটাগরি, দপ্তর, স্টক ইন/আউট, লেনদেন, সেটিংস) ব্রাউজারের **localStorage**-এ সংরক্ষিত থাকে। এর মানে:

- Page Refresh করলে বা Browser বন্ধ করে আবার খুললে ডেটা থাকবে।
- ডেটা শুধুমাত্র সেই একই ব্রাউজার ও একই ডিভাইসে সংরক্ষিত থাকে (অন্য কম্পিউটার বা ব্রাউজারে স্বয়ংক্রিয়ভাবে যাবে না)।
- ব্রাউজারের Cache/Site Data মুছে ফেললে ডেটা হারিয়ে যেতে পারে — তাই নিয়মিত ব্যাকআপ নেওয়ার পরামর্শ দেওয়া হচ্ছে (নিচে দেখুন)।
- ভবিষ্যতে Firebase বা Supabase-এর মতো ব্যাকএন্ড যুক্ত করার জন্য কোডে একটি আলাদা `DB` অবজেক্ট/লেয়ার রাখা হয়েছে, যাতে শুধু সেই লেয়ারটি পরিবর্তন করলেই হয়।

## Backup/Restore ব্যবহারের নিয়ম

- **সেটিংস → ব্যাকআপ ডাউনলোড করুন** বাটনে ক্লিক করলে সম্পূর্ণ ডেটা একটি `.json` ফাইল হিসেবে ডাউনলোড হবে। এই ফাইলটি নিরাপদ জায়গায় (যেমন Google Drive, Pen Drive) রাখুন।
- ডেটা হারিয়ে গেলে বা নতুন ডিভাইসে ব্যবহার করতে চাইলে **সেটিংস → রিস্টোর করুন** বাটনে ক্লিক করে পূর্বে ডাউনলোড করা `.json` ফাইলটি নির্বাচন করুন। রিস্টোর করার আগে একটি নিশ্চিতকরণ বার্তা দেখানো হবে, কারণ এটি বর্তমান সকল ডেটা প্রতিস্থাপন করবে।

## গুরুত্বপূর্ণ নোট

- এটি একটি Client-side (শুধুই ব্রাউজার-নির্ভর) সফটওয়্যার। কোনো ব্যাকএন্ড/সার্ভার/ডাটাবেজ নেই বলে একাধিক ব্যবহারকারী একইসাথে একই ডেটা শেয়ার করতে পারবেন না — প্রতিটি ব্রাউজার/ডিভাইসের ডেটা আলাদা।
- একাধিক ব্যবহারকারীর জন্য কেন্দ্রীয় ডেটাবেজ প্রয়োজন হলে ভবিষ্যতে Firebase/Supabase Backend যুক্ত করার সুযোগ রেখেই কোড তৈরি করা হয়েছে।
